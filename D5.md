## Part 2: Custom MFA with Security Questions

### Goal

Add a second authentication factor to SSH:

**Before:**
```
SSH Login → Password check → Access granted ✓
```

**After:**
```
SSH Login → Password check → Random security questions → Access granted ✓
```

### Why This Matters

Even if someone cracks your password, they can't log in without answering randomized security questions. Two factors = two barriers to entry.

---

### Implementation

#### Step 1: Create Security Questions Config

Created `~/.ssh/mfa_questions` with 8 Q&A pairs:

```
question_1|What's your first pet's name?|juice
question_2|What city were you born in?|hong kong
question_3|What's your favorite OS?|linux
question_4|What's your favorite type of coffee?|short black
question_5|What's your mother's name?|florence
question_6|What's your favorite coffee shop?|cosmos
question_7|What's Ryan's type?|girls with big eyes
question_8|Messi or Ronaldo?|deji
```

#### Step 2: Build MFA Python Script

Created `~/.ssh/mfa_auth.py` that:
- Reads the config file
- Randomly selects 2 questions from 8 (different every login)
- Prompts user for answers
- Validates answers (case-insensitive: "Juice" = "juice")
- Logs attempts
- Returns exit code 0 (success) or 1 (fail)

**Standalone test:** ✅ Worked perfectly

---

### Problem: PAM Integration Failed ❌

**What I tried:**

```bash
sudo nano /etc/pam.d/sshd
# Added: auth required pam_exec.so /home/ryan/.ssh/mfa_auth.py
```

**What went wrong:**

When I tried to SSH in after entering the password:
```
SSH: Permission denied, please try again
```

The MFA questions never appeared.

**Root cause:**

PAM runs scripts **without a proper terminal** in the background. This meant:
- My script couldn't display the security questions
- I couldn't type my answers
- The script crashed silently
- SSH rejected the login

Plus I had **permission issues** - the script couldn't read the config file because `.ssh` was locked down too tight (chmod 700).

**Attempted fixes:**
```bash
chmod 644 ~/.ssh/mfa_questions   # Allow root to read config
chmod 755 ~/.ssh                 # Allow root to access directory
```

**Result:** Still failed. PAM fundamentally can't handle interactive terminal I/O.

---

### Solution: SSH Wrapper Script ✅

**The fix:**

Instead of using PAM, I created a **wrapper script** as my login shell:

```bash
nano ~/.ssh/ssh_login_wrapper.sh
```

```bash
#!/bin/bash
# MFA wrapper for SSH login

python3 ~/.ssh/mfa_auth.py

if [ $? -eq 0 ]; then
    # MFA passed, launch the real shell
    exec /bin/bash -l
else
    # MFA failed, exit
    exit 1
fi
```

**Make it executable:**
```bash
chmod +x ~/.ssh/ssh_login_wrapper.sh
```

**Set as login shell:**
```bash
sudo chsh -s /home/ryan/.ssh/ssh_login_wrapper.sh ryan
```

**Why this works:**

The wrapper script runs **inside my active SSH session** with a real terminal. Now:
1. I SSH in and enter password
2. SSH verifies it → launches wrapper script
3. Wrapper runs MFA in the same terminal
4. I can see questions and type answers
5. Wrapper launches bash on success ✅

## Lessons Learned

1. **PAM is powerful but complex** — System-wide authentication framework, difficult to debug interactively
2. **Choose the right tool for the job** — SSH wrapper script was simpler than forcing PAM to work
3. **Permissions matter for privileged processes** — Root needs read access to config files
4. **Interactive programs need real terminals** — Scripts run by PAM lack proper I/O
5. **Test before system integration** — Always verify scripts work standalone first
